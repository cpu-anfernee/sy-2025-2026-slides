The Core SQL Query Structure

The basic structure of an SQL expression consists of three essential clauses:

  • SELECT: Specifies the columns desired in the final result network.
  • FROM: Lists the relations (tables) to be scanned during execution.
  • WHERE: Defines a predicate filter condition that rows must satisfy.

This maps directly back to the pure mathematical operators of Relational Algebra!

The SELECT Clause

Corresponds to the Project ($\Pi$) operation in relational algebra. It identifies the target attributes to return:

SELECT name, dept_name 
FROM instructor;
  • SQL allows duplicates: Unlike pure mathematical sets, SQL tables are multisets. If multiple instructors have the same name, they all appear.
  • To force duplicate elimination, use the DISTINCT keyword:
    SELECT DISTINCT dept_name FROM instructor;
  • Alternatively, the ALL keyword explicitly preserves duplicates (default behavior).

The SELECT Clause cont.

You can add arithmetic expressions involving the operators +, -, *, and / operating on constants or attributes of tuples.

SELECT ID, name, dept_name, salary * 1.1 
FROM instructor;

The WHERE Clause

Corresponds to the Select ($\sigma$) operation in relational algebra. It filters out rows that fail a logical predicate:

SELECT name 
FROM instructor 
WHERE dept_name = 'Comp. Sci.' AND salary > 70000;
  • SQL supports logical connectives: AND, OR, and NOT.
  • Comparison operators include: <, <=, >, >=, =, and <> (Not Equal).
  • Can use the BETWEEN operator for range evaluations:
    WHERE salary BETWEEN 60000 AND 80000;

The FROM Clause & Joins

Corresponds to the Cartesian Product ($\times$) operation. It combines rows from multiple target source tables:

SELECT name, building 
FROM instructor, department 
WHERE instructor.dept_name = department.dept_name;
  • If a column name exists in multiple tables (e.g., dept_name), you must prefix it with the table name to avoid ambiguity.
  • Under the Hood: The engine conceptually pairs every row from table A with every row from table B, then drops combinations that fail the WHERE join predicate matching rule.

Summary of Basic SQL Queries

  1. The Big Three: SELECT (Project), FROM (Cartesian Product), and WHERE (Filter) construct the standard relational query template.
  2. Multiset Behavior: SQL defaults to leaving duplicates alone unless you explicitly clear them out using the DISTINCT filter.
