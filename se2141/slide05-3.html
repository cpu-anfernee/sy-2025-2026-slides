3.4.1 The Rename Operation

SQL provides the AS clause (taking the form old-name AS new-name) to rename attributes and relations:

  • Renaming Attributes: Useful when attributes share names across tables, results involve expressions, or clearer labels are needed. 
    SELECT name AS instructor_name, course_id
FROM instructor, teaches
WHERE instructor.ID = teaches.ID;
  • Renaming Relations (Correlation Names / Table Aliases): Essential for shortening long table names or taking the Cartesian product of a relation with itself. 
    SELECT DISTINCT T.name
FROM instructor AS T, instructor AS S
WHERE T.salary > S.salary AND S.dept_name = 'Biology';

3.4.2 String Operations

SQL encloses string constants in single quotes (e.g., 'Computer') and uses two single quotes to embed a quote (e.g., 'It''s right').

  • Case Sensitivity: Standard SQL string comparisons are case sensitive ('comp. sci.' = 'Comp. Sci.' is false), though engines like MySQL or SQL Server differ by default.
  • String Functions: Built-in support for concatenation (||), upper(s), lower(s), trim(s), and substring extraction.
  • Pattern Matching with LIKE:
    • % matches any substring. (e.g., 'Intro%', '%Comp%')
    • _ matches any single character. (e.g., '___' for 3 characters, '___%' for at least 3)
    • Use ESCAPE to match literal wildcard characters: LIKE 'ab\%cd%' ESCAPE '\'

3.4.3 - 3.4.5 Additional Clauses

  • 3.4.3 Attribute Specification: Use * to select all attributes (e.g., instructor.* or SELECT *).
  • 3.4.4 Ordering the Display: Sort query outputs using ORDER BY with optional DESC or ASC modifiers across multiple attributes. 
    SELECT * FROM instructor ORDER BY salary DESC, name ASC;
  • 3.4.5 Where-Clause Predicates:
    • BETWEEN ... AND ... (and NOT BETWEEN) simplifies range checks.
    • Row Constructors: Compare tuples lexicographically using (v1, v2, ..., vn).
      WHERE (instructor.ID, dept_name) = (teaches.ID, 'Biology');

3.5 Set Operations in SQL

SQL operations UNION ($\cup$), INTERSECT ($\cap$), and EXCEPT ($-$ / set difference) operate on relations.

  • Automatic Duplicate Elimination: Unlike regular SELECT clauses, set operations automatically eliminate duplicates by default!
  • To retain all duplicates, use UNION ALL, INTERSECT ALL, or EXCEPT ALL.

Multiset Set Operations Mechanics

Suppose relation $c_1$ has $m$ copies of a tuple, and relation $c_2$ has $n$ copies:

  • UNION ALL: Produces $m + n$ duplicate copies in the result.
  • INTERSECT ALL: Produces $\min(m, n)$ duplicate copies in the result.
  • EXCEPT ALL: Produces $\max(0, m - n)$ duplicate copies in the result.

Implementation Note: Oracle uses MINUS instead of EXCEPT; MySQL does not support INTERSECT or EXCEPT directly.

3.6 Null Values & Arithmetic

NULL indicates missing, unknown, or non-applicable attribute values, introducing special behavior in queries:

  • Arithmetic Propagation: Any arithmetic expression (+, -, *, /) involving a null yields null (e.g., $r.A + 5$ evaluates to null if $r.A$ is null).
  • Comparisons Yield UNKNOWN: Any comparison like 1 < null evaluates to unknown.
  • This introduces a Three-Valued Logic system: TRUE, FALSE, and UNKNOWN.

Three-Valued Logic (3VL)

Definitions of Boolean operations extended for UNKNOWN:

  • AND:
    • true AND unknown $\rightarrow$ unknown
    • false AND unknown $\rightarrow$ false
    • unknown AND unknown $\rightarrow$ unknown
  • OR:
    • true OR unknown $\rightarrow$ true
    • false OR unknown $\rightarrow$ unknown
    • unknown OR unknown $\rightarrow$ unknown
  • NOT: NOT unknown $\rightarrow$ unknown

The WHERE clause predicate discards tuples if it evaluates to either FALSE or UNKNOWN.

Testing Nulls & Set Equality

  • Null Predicates: Test missing values using IS NULL, IS NOT NULL, or test logic using IS UNKNOWN / IS NOT UNKNOWN. 
    SELECT name FROM instructor WHERE salary IS NULL;
  • Null Equality in SELECT DISTINCT & Set Operations:
    • In WHERE comparisons, null = null evaluates to UNKNOWN.
    • HOWEVER, for SELECT DISTINCT, UNION, INTERSECT, and EXCEPT, two null values are treated as identical (e.g., {('A', null), ('A', null)} collapses to 1 row).

Null Treatment Inconsistencies

Notice the contradiction in how SQL treats NULL values:

  • In a WHERE clause predicate, comparing null = null results in UNKNOWN, failing the condition.
  • In SELECT DISTINCT or UNION operations, two tuples with NULL values in the same attribute are treated as identical duplicate rows.

Summary of 3.4 - 3.6

  1. Renaming & Strings: Use AS for aliasing. SQL supports string pattern matching via LIKE with % and _ wildcards.
  2. Set Operations: UNION, INTERSECT, and EXCEPT eliminate duplicates by default; append ALL to preserve multiset counts.
  3. Three-Valued Logic: Comparisons with NULL evaluate to UNKNOWN. Predicates only pass tuples evaluating to TRUE.
  4. Null Equality Dualism: Nulls are UNKNOWN in predicates but treated as identical duplicates in DISTINCT and set operations.
