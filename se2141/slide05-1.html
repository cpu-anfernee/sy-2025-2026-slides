What is SQL?

SQL (Structured Query Language) is the industry-standard language designed specifically for managing data held in a relational database management system.

  • Its Purpose: To provide a universal, declarative syntax for defining data structures, querying information, and controlling system access parameters.
  • Declarative Power: You tell the database engine what dataset you want, not the step-by-step algorithms of how to parse files on disk.

Discussion: Why One Language Standard?

  • Almost every relational database uses a variant of SQL (ISO standard).
  • Discussion Question: How does having a single, widely adopted database language standard benefit you as software engineers working with different backend tech stacks over your career?

The Two Faces of SQL

SQL statements are fundamentally split into two primary working components:

  • Data Definition Language (DDL): Statements used to create, alter, drop, and configure the structural blueprints (schemas) of database objects.
  • Data Manipulation Language (DML): Statements used to query, insert, update, or remove actual data tuples within those structural frameworks.

We shall start with DDL (Data Definition)!

3.2 Standard Domain Types

Before creating tables, we must choose appropriate data domains. The SQL standard provides several core primitive types:

  • char(n): Fixed-length character string of length $n$.
  • varchar(n): Variable-length character string with a maximum length $n$.
  • int: A standard signed machine integer.
  • smallint: A small integer
  • numeric(p, d): Fixed-point decimal number with precision $p$ digits total, and $d$ numbers to the right of the decimal point. (Essential for currency!)
  • float(n): Floating-point number with precision of at least $n$ digits.

The CREATE TABLE Command

We instantiate a relation schema layout using the CREATE TABLE block format:

CREATE TABLE department (
    dept_name   VARCHAR(20),
    building    VARCHAR(15),
    budget      NUMERIC(12, 2),
    PRIMARY KEY (dept_name)
);
  • Attributes are separated by commas.
  • Data types must be explicitly assigned to each field attribute.
  • Integrity constraints (like keys) are declared at the bottom.

Enforcing Database Rules

The SQL DDL allows us to declare rules that the engine automatically enforces on data adjustments:

  • PRIMARY KEY (A_1, A_2, ...): Ensures values are non-null and completely unique across rows.
  • FOREIGN KEY (A_1, A_2) REFERENCES s: Ensures values must match values in the primary key of target relation $s$.
  • NOT NULL: Explicitly forbids a specific attribute from storing null values.

Putting Constraints Together

Let's look at a schema mapping that includes foreign key validation pointers:

CREATE TABLE instructor (
    ID          CHAR(5),
    name        VARCHAR(20) NOT NULL,
    dept_name   VARCHAR(20),
    salary      NUMERIC(8, 2),
    PRIMARY KEY (ID),
    FOREIGN KEY (dept_name) REFERENCES department(dept_name)
);

Modifying Existing Tables

What happens when your structural design schema inevitably needs updates?

  • DROP TABLE: Deletes both the table data instance AND the structural schema from the database catalog entirely.
    DROP TABLE instructor;
  • ALTER TABLE: Modifies columns of an existing table without destroying the structural schema block.
    ALTER TABLE instructor ADD middle_name VARCHAR(15);
    ALTER TABLE instructor DROP COLUMN salary;

Summary of SQL Data Definition

  1. SQL is Declarative: It handles data structures safely without you coding memory pointers or file paths manually.
  2. DDL Controls Schema: The CREATE TABLE command binds explicit domain types (like int, varchar, or numeric) to attributes.
  3. Constraints Enforce Reality: Declaring PRIMARY KEY and FOREIGN KEY keeps data reliable at the database engine layer.
  4. Evolution Commands: ALTER TABLE and DROP TABLE provide mechanisms to update schemas over time.
