What is TypeScript?


// Specifying that 'password' MUST be a string
function validatePasswordLength(password: string) {
  return password.length >= 8;
}

// Error caught in editor!
validatePasswordLength(123456789); 
// Argument of type '123456789' is not 
// assignable to parameter of type 'string'.
  • TypeScript is a typed superset of JavaScript that compiles to plain JavaScript.
  • It allows you to specify types for values, enabling you to develop with more confidence.
  • TypeScript tells you if you have an error just by analyzing the syntax, meaning you don't even have to run your program.

Defining Custom Types

Going beyond built-in types like strings and numbers.

  • You can define custom shapes for your objects to ensure functions receive the correct input.
  • Functions will only accept objects that match the explicitly defined type (e.g., a User type).

type User = {
  firstName: string;
  lastName: string;
};

function greet(user: User) {
  return `Hello ${user.firstName} ${user.lastName}`;
}

Benefits of Using TypeScript

  • Preventing errors: It provides clear contracts of communication between parts of your program. Research shows typed languages yield 15% fewer bugs.
  • Rock-solid stability: When combined with unit tests, pre-release bug density can be reduced by 40% to 90%.
  • Better Developer Experience: Provides better code suggestions in your editor, making it easier to navigate unfamiliar codebases.

Why TS with React?

Enhancing component-based architecture.

  • React allows passing information and callbacks down the component tree.
  • TypeScript defines the interfaces of your components to ensure they only receive props with the correct types.
  • Why not just use prop-types?
    • TypeScript spots errors in your editor without running the app.
    • It can provide types for standard functions and classes outside of React.
    • It is fundamentally more powerful in defining complex type information.

A Necessary Word Of Caution

Type Checking != Runtime Safety

TypeScript does not catch run-time type errors. You can write code that passes the type checker but throws an error upon execution.

  • If you declare an array as Array<string | number> and pass it strings, it passes the type check.
  • If a number slips in and you run a string method like toLowerCase() on it, your app will crash.
  • You must be extra careful with data obtained through network requests or loaded from the file system, as their true runtime shape can differ from your types.
